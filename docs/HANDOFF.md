# Handoff - continuing development on a new machine

Written 2026-07-03, at the end of the Phase 0-3d build. This file plus the other
docs makes the repo fully self-sufficient: a fresh Claude session on any machine
needs NOTHING from prior chat history. Read order for a new session:
**CLAUDE.md -> docs/PLAN.md -> this file** (deep background: ARCHITECTURE.md,
STRATEGY_SPEC.md, COSTS_AND_TAX.md, REVIEW_PHASE_0-3.md).

## The study run (owner, ~overnight)

1. **Pull + inspect** (network-bound, 1-2 h):
   `python -m scripts.pull_data --start 2005-01-01` then
   `python -m scripts.data_quality`. GATE YOURSELF on the output: a large skip
   count (ticker-format mismatches like BRK.B) or failed split checks means
   stop and investigate, not proceed on a thin panel.
2. **FX file**: Danmarks Nationalbank StatBank series DNVALD, USD row, quoted
   kroner-per-100-units -> **divide by 100** -> a `date,rate` CSV with values
   ~5-9. The runner rejects wrong-scale files with a diagnostic (see
   research/README.md).
3. **Smoke the pipeline** (minutes), isolated so the real trials ledger stays
   pure: `python -m scripts.run_research --candidates c --limit 60
   --start 2015-01-01 --fx-csv usd_dkk.csv --out-dir research_smoke`, then
   DELETE research_smoke/ (plumbing check, not research).
4. **Real run** (tens of hours; disable machine sleep):
   `python -m scripts.run_research --start 2005-01-01 --fx-csv usd_dkk.csv`.
   Never pass `--no-stress` - the doubled-cost line is a binding gate criterion.
5. **Commit** research/trials.csv + research/REPORT.md, push, then read the
   report WITH the reviewer against the Gate 3G criteria. The parameter-plateau
   check is a human judgment on the surface tables, deliberately not automated.
6. **The 2-year holdout is one-shot and sealed.** It is not produced by the
   study run and must not be run until owner + reviewer explicitly approve.

## Working agreements (from the build sessions; supplements CLAUDE.md)

- Roles: **Fable** = planner/reviewer (wrote PLAN/specs, reviewed Phases 0-3 in
  REVIEW_PHASE_0-3.md), **Opus** = implementer. The owner switches models
  explicitly per task; implementation prompts go to Opus, review/go-no-go
  questions to Fable.
- One PR per phase (or sub-phase a/b/c/d for large ones), branch `phaseN-slug`,
  squash-merge, update PLAN.md's status table as PRs open/merge.
- Codex review loop: comment `@codex review`; per finding: fix + push + reply on
  the thread + resolve it; re-request; merge on a clean pass. **Fallback agreed
  with the owner:** when Codex is at its usage cap (it posts "reached your Codex
  usage limits"), a rigorous self-review + merge on clean objective state
  (0 unresolved threads, CI green, MERGEABLE) is acceptable; say so in the merge
  message.
- Local gate BEFORE every push: `ruff check .` AND `ruff format --check .` AND
  `pytest` (CI runs all three; format-only failures have burned us).
- Do not clone into OneDrive/Dropbox-synced folders - file virtualization broke
  git validation on the previous machine. Use a plain local path.
- Suggested opening prompt for a fresh implementation session:
  "Read CLAUDE.md, docs/PLAN.md and docs/HANDOFF.md in this repo, then <task>."
